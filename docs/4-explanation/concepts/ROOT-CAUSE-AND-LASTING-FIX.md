# Root cause and lasting fix

*Also called:* root cause analysis, RCA, CAPA, corrective and preventive action, five whys

**What it is:** Finding the real reason a mistake happened, then changing the process so it cannot happen again.

**Why it matters:** Fixing only the one case leaves the cause in place, so the same kind of mistake comes back.

**The rule here:** A fix is not done until it stops the repeat, not just this case. Each fix names the cause it removes.

**How to use it:** Ask why the mistake happened. Then ask why again, until you reach something you can change. Change it, and add a check.

**Next step:** Pick a mistake that came back, and write down its cause in one line.

## How it connects

The best lasting fix is [mistake-proofing](MISTAKE-PROOFING.md). A test that stops a [backslide](BACKSLIDE.md) keeps the fix in place.

**Source:** US regulation [21 CFR 820.100, Corrective and preventive action](https://www.ecfr.gov/api/renderer/v1/content/enhanced/2024-01-01/title-21?part=820&section=820.100) (text as of 2024; replaced in 2026 by a rule that brings in ISO 13485): finding `cps-14` in the [concept page sources card](../../../research/corpus/concept-page-sources.md), status checked. The ask-why-again method is common practice, not from this source.
